USO Bot AI Upgrade - Master Development Prompt

Project Goal

Upgrade the existing USO Bot into an AI-powered Discord assistant while preserving every existing feature, command, and workflow. This is an enhancement project—not a rewrite.

The AI should make USO Bot feel like another member of the server: funny, intelligent, helpful, and engaging, while remaining respectful of server settings and Discord permissions.

⸻

🚨 CRITICAL REQUIREMENTS

DO NOT REWRITE THE BOT

This is extremely important.

* DO NOT delete existing commands.
* DO NOT rename existing commands.
* DO NOT remove existing features.
* DO NOT break current slash commands.
* DO NOT remove current event handlers.
* DO NOT replace working code simply because there is a different way to do it.
* Preserve the current project structure whenever possible.
* Build around the existing architecture.
* Only refactor when absolutely necessary.
* If code must change, maintain backward compatibility.
* Existing users should not notice any lost functionality after the upgrade.

Analyze the existing codebase first and reuse as much of it as possible.

⸻

AI Architecture

Create a modular AI system that plugs into the current bot.

Example structure:

ai/
│
├── brain.py
├── prompts.py
├── memory.py
├── scheduler.py
├── tools.py
├── permissions.py
├── personalities.py
├── conversation.py
├── cooldowns.py
└── settings.py

Keep AI separated from Discord command logic.

⸻

OpenAI Integration

Integrate OpenAI.

The AI should:

* Hold natural conversations
* Understand intent
* Decide whether to answer normally or use an existing bot function
* Call existing commands/functions whenever possible
* Never duplicate functionality that already exists

The AI becomes the decision-making layer.

Final Development Requirements

Before changing any code:

1. Analyze the current project.
2. Document the existing architecture.
3. Identify reusable systems.
4. Preserve every existing command and feature.
5. Build the AI as a modular layer on top of the current bot.
6. Refactor only when necessary.
7. Maintain backward compatibility.
8. Keep code clean and modular.
9. Document every change made.
10. At the end, provide:

* A summary of new features.
* A list of reused components.
* A list of modified files.
* A list of newly created files.
* Any recommendations for future improvements.

Success Criteria

The finished project should feel like the same USO Bot, only much smarter.

Users should be able to interact naturally by mentioning the bot, while all existing commands continue to work exactly as before.

USO should become a memorable member of the server—funny, engaging, intelligent, and genuinely useful—without overwhelming conversations or disrupting the current user experience.
